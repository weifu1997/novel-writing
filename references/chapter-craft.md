# 章法颗粒路由

章法解决“这一章怎样组织才产生预期阅读效果”，题材工艺解决“用什么生活、规则和冲突材料来写”。先读取 [chapter-craft/scene-architecture.md](chapter-craft/scene-architecture.md)，再根据本章主任务只完整加载一张主章法卡；确有第二任务时，最多摘取一张辅卡的相关段落。

## 路由

| 本章主要任务 | 主章法卡 | 不要用这张卡的情况 |
|---|---|---|
| 建立全书承诺、人物处境或第一项不可逆问题 | [chapter-craft/opening.md](chapter-craft/opening.md) | 中后段只推进既有问题，没有新的读者契约 |
| 控制答案、秘密、悬念或读者/人物信息差 | [chapter-craft/information-suspense.md](chapter-craft/information-suspense.md) | 本章主要靠行动或关系选择结算，秘密只是背景 |
| 通过谈判、冲突、试探或亲密行为改变关系 | [chapter-craft/dialogue-relationship.md](chapter-craft/dialogue-relationship.md) | 对话只是交代信息，关系本身没有代价 |
| 战斗、追逐、逃脱、竞赛或高强度行动 | [chapter-craft/action-conflict.md](chapter-craft/action-conflict.md) | 打斗可删且不影响选择与后果 |
| 调查、推理、取证、验证假设或揭穿谎言 | [chapter-craft/investigation-evidence.md](chapter-craft/investigation-evidence.md) | 没有可核验证据，只是气氛紧张 |
| 阶段高潮、承诺兑现、重大选择及后果落地 | [chapter-craft/climax-aftermath.md](chapter-craft/climax-aftermath.md) | 本章只铺垫，高潮结算仍在后续章 |
| 低压、过渡、转场、阶段收束或卷尾继承 | [chapter-craft/transition-volume-end.md](chapter-craft/transition-volume-end.md) | 本章仍有必须结算的主冲突 |

“开篇”是建立读者契约的章节功能，不等于固定前三章；“高潮”也不等于打斗。混合章节先确定主要状态变化由哪种章法负责，辅卡不能把一章拆成互不结算的两套流程。

## 章法执行卡

在现有章纲之后补齐以下内部字段，不必把术语写入正文：

```markdown
- 主章法 / 辅章法：
- 入口状态：人物、读者和对手分别处于什么位置
- 本章主问题：结束前必须被改变的问题
- 压力材料：本题材中什么具体人、物、规则或时限在施压
- 升级台阶：人物原办法为何不够，下一步为何更贵或更危险
- 中段转轴：哪项信息、行动或关系反应改变了场景方向
- 关键选择：谁作出不能由别人代替的决定
- 结算：本章兑现什么，代价落给谁
- 退出状态：信息、关系、目标、风险、资源或情绪位置的 before -> after
- 章尾债务：由退出状态自然产生的下一问题
```

字段描述功能，不预写金句，不按百分比给段落配额。场景数量由因果需要决定；一个场景能完整完成主问题时，不为“丰富”硬加转场。

## 验收

- 章中每次升级都由上一动作或新证据造成，不靠作者突然加码。
- 转轴前后，人物的可用办法或读者理解确实改变。
- 高光和答案归属于此前承担因果与选择的人。
- 结算既不是重复总结，也没有把下一章正文提前写完。
- 删除人名和题材名后仍能看见因果结构；换成任意人物也成立则说明人物选择仍太泛。
- 章法卡是决策工具，不是固定模板；正文不得出现“入口、转轴、结算、章尾债务”等工程词。
