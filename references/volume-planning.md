# 中长篇卷规划

本协议适用于约 30-150 章的中长篇，也用于超长篇的单卷规划。目标是在足够远的方向感与足够近的可执行性之间保持滚动精度，而不是提前写死所有章节。

## 四层分辨率

```text
全书承诺（低分辨率，直到终局）
  -> 卷合同（中分辨率，当前卷）
    -> 剧情单元（高分辨率，通常 3-8 章）
      -> 单章执行卡（精确，只做下一章或已授权范围）
```

- 全书层锁定核心承诺、终局变化、不可提前消耗的答案和大阶段顺序。
- 当前卷层明确入口、阶段目标、不可逆转折、卷终选择和继承项。
- 下一剧情单元逐章规划；更远单元只保留功能和依赖，临近时再展开。
- 单章执行卡使用 `workflow.md` 的章纲字段，并绑定字数合约。

30-150 章不是固定卷长。故事较短时可以只有一卷，超长篇则每卷重复本协议。规划粒度由因果可见度决定，不用固定爽点频率填表。

## 规划前输入

只读取会改变规划的材料：

- 读者承诺、主角欲望与失败代价、终局方向。
- `Genre Contract` 与 `Style Contract`。
- 总篇幅、单章字数和平台等已确认约束。
- 已接受状态、活跃剧情债务、人物弧位置和上一卷结算。
- 用户已锁定的必发生、禁止发生和不可提前揭露信息。

尚未确认的判断标为“工作假设”。大纲中的未来事件是计划，不得写入已接受事实库。

## 全书承诺页

```markdown
# 全书承诺
- 一句话故事承诺：
- 主角持续欲望 / 核心缺口：
- 失败代价：
- 核心冲突发动机：
- 终局必须发生的变化：
- 预计总章数 / 总字数 / 计数口径：
- 阶段地图：每阶段只写入口、核心问题、不可逆变化、出口
- 终局储备：身份、真相、能力、关系中哪些不得提前耗尽
- 已锁定项：
- 工作假设及验证点：
```

阶段地图是导航，不预演所有场景。后续卷可以调整路线，但调整不得悄悄覆盖已经发生的事实或用户锁定项。

## 卷合同模板

```markdown
# 第 N 卷：卷名
- 规划版本 / 日期：
- 章节范围与字数预算：预计值，不冒充已发生数据
- 入口状态：引用已接受 commit、章节或正文证据
- 本卷核心问题：卷末必须得到何种阶段答案
- 阶段目标：主角主动争取什么
- 对抗压力：谁或什么持续阻止，为什么不会一次解决
- 升级阶梯：难度、代价、关系、认知、规模如何发生不同变化
- 中点或阶段转折：哪项不可逆事实迫使人物更换办法
- 卷终选择与结算：谁选择、付出什么、哪些承诺得到兑现
- 人物弧：每位核心人物的 before -> 压力 -> 选择 -> after
- 剧情债务与伏笔日程：本卷新增、推进、回收、允许跨卷的项目
- 新元素预算：新增人物、地点、势力、规则各自承担什么必要功能
- 禁止提前揭露：
- 下一卷继承项：状态、债务、关系、资源和未解问题
- 风险与退出条件：何种信号说明本卷方案需重排
- 验收：卷末如何证明核心问题、人物弧和债务确已结算
```

“升级阶梯”写变化维度，不机械规定每几章出现一次高潮。“新元素预算”用于抑制无功能扩张，不是数量上限。

## 剧情单元模板

一个单元围绕一项可结算的问题，通常覆盖 3-8 章；复杂任务可以更长，但应说明原因。

```markdown
## 单元 Uxx：名称（预计第 A-B 章）
- 入口压力：
- 单元问题 / 可验证出口：
- 人物欲望与当前办法：
- 阻力如何迫使办法升级：
- 必须使用的既有事实 / 线索 ID：
- 不得触碰的后期储备：
- 关键选择与代价：
- 单元结算：信息、关系、目标、风险、资源或情绪位置改变什么
- 新债务：为什么进入下一单元
- 若人物作出不同选择：允许的重排方向
```

只把下一单元展开成逐章任务：

| 章 | 入口压力 | 本章欲望 | 阻力与选择 | 状态变化 | 承接 / 新债务 | 字数合约 | 状态 |
|---|---|---|---|---|---|---|---|
| N |  |  |  |  |  |  | planned |

表中只写功能与因果，不预写正文金句，不强配同一种情绪曲线或章尾钩子。

## 规划记忆视图

规划文件是未来路线与方便阅读的投影视图，不是第二事实源。每次滚动规划在文件头标明：

```yaml
plan_revision: 3
based_on_state_revision: 27
accepted_through_chapter: ch-026
current_volume: vol-01
next_unit: U05
assumptions:
  - id: A03
    claim: 对手可能在卷中点主动结盟
    status: open
decisions:
  - id: D08
    decision: U04 延后一章结算
    reason: 第 24 章的人物选择改变了进入条件
```

- `accepted_through_chapter` 之前的事实以数据库或已接受正文为准。
- 计划表里的 `planned`、`candidate`、`discarded` 不得被续写当成既成事实。
- 章节提交后，从事实源刷新入口状态，再调整后续计划；不能用旧计划反向覆盖新事实。

## 滚动重排

每个剧情单元结束后：

1. 对比“计划出口”与“实际已接受状态”。
2. 标出已兑现、延期、作废和新生的剧情债务。
3. 检查人物是否作出超出原计划但成立的选择。
4. 保持卷合同不变时，只重排下一单元；若卷核心问题或卷终结算已失效，升格为卷合同修订并说明影响。
5. 只把下一单元展开为逐章卡，远期仍保留低分辨率。

改动已经接受的旧章不属于“重排计划”，必须走影响分析与 revision 流程。

## 卷末验收

- 卷核心问题有明确阶段答案，卷终选择改变了后续条件。
- 核心人物弧有正文证据，未把态度宣言当成完成变化。
- 剧情债务逐项标记为回收、延期并支付进展、作废并有原因，或明确继承。
- 时间线、伏笔和连续性审计通过；结构化项目以持久化 `volume_audit` 为准。
- 比较卷首、卷中和卷尾样章，检查视角、声口、句段节奏和题材体验是否漂移。
- 下一卷继承项来自卷末已接受状态，不从旧卷纲复制。
