# 分阶段拆文与写作召回

本协议把合法可读的对标文本转化为可追溯的写作决策资产。它扩展 [comparative-analysis.md](comparative-analysis.md)：后者用于小范围决策拆解；本协议用于需要落盘、续跑、跨阶段聚合和后续召回的完整拆文。

## 权限与边界

- 只处理用户提供、用户有权使用、公共领域或合法公开可读的文本。
- 不绕过付费、登录或访问控制抓取原文。
- 用户没有提供可保存全文的权限时，只保存来源、哈希、位置和必要短引文，不复制整部作品。
- 拆解是转化性分析；输出功能、条件、证据和失败模式，不生成替换专名即可复刻的剧情蓝图。

## 标准工作区

用确定性工具初始化：

```bash
python "<skill-dir>/scripts/analysis_workspace.py" init \
  --workspace "<项目根>/拆文库/<作品名>" \
  --source "<合法文本文件>" --title "<作品名>" --kind long --json
```

短篇使用 `--kind short`。工具保存源文件哈希和章节边界；只有显式追加 `--snapshot-source` 才把源文件副本写入工作区。已存在工作区不会被覆盖。

```text
拆文库/{作品名}/
|-- _meta.json
|-- 来源.md
|-- 概要.md
|-- 开篇.md
|-- 章节/
|-- 剧情/
|   |-- 单元.md
|   |-- 节奏.md
|   `-- 情绪与承诺.md
|-- 人物与关系.md
|-- 设定与机制.md
|-- 章法.md
|-- 文风.md
|-- 召回卡.md
`-- 拆文报告.md
```

按需创建当期阶段需要的文件，不预建空产物。`_meta.json` 是管道进度与来源清单，不是对标作品事实的替代品；事实结论仍要指向来源位置。

## 阶段管线

### Stage 0：来源与边界

- 验证来源、编码、哈希、版本和授权说明。
- 长篇确定章节边界、重复章、缺章和顺序；短篇确定全文与小节边界。
- 输出 `来源.md`、章节边界和覆盖限制。

### Stage 1：开篇停靠点

- 长篇拆开篇承诺、主角驱动、核心机制首次作用、信息负担和首个继续阅读债务；默认覆盖前三个有效章节，但以功能完整性为准。
- 短篇拆开头、故事核、主问题和第一个不可逆选择。
- 输出 `开篇.md`，可在此停靠，让用户决定是否继续全量拆解。

### Stage 2：逐章 / 逐场景提取

每个单元记录：入口状态、人物欲望、阻力、选择、代价、状态变化、新债务、线索、人物弧、章法类型和精确来源位置。只提取文本实际发生内容；推断标 confidence。

长文本分批处理，但按章号稳定落盘；失败章写入 `_meta`，不能在聚合时静默消失。

### Stage 3：聚合结构

- 合并剧情单元、主副线和循环机制。
- 建立情绪/压力曲线、信息释放、承诺兑现和跨章伏笔图。
- 区分重复机制的稳定核心与每轮变化条件。
- 输出 `剧情/单元.md`、`剧情/节奏.md`、`剧情/情绪与承诺.md`。

### Stage 4：人物、设定与章法

- 合并别名后分析人物目标、选择模式、关系变化和功能位。
- 提取世界规则、能力/职业机制、资源和限制。
- 归纳开篇、信息、关系、行动、调查、高潮、低压与卷尾如何组织，附适用条件和失败模式。
- 输出 `人物与关系.md`、`设定与机制.md`、`章法.md`。

### Stage 5：文风与表达

分析视角、叙事距离、句段节奏、对话策略、意象来源和信息留白。文风结论与结构结论分开；只保留必要短引文作为证据，形成不可直接模仿特定作品表达指纹的抽象 Style Profile。

### Stage 6：综合报告与召回卡

- `拆文报告.md` 汇总读者承诺、结构、人物、机制、章法、文风、局限和证据覆盖。
- `召回卡.md` 只保留下游可调用的功能结论、适用条件、来源、相似性风险和失败条件。
- 回填扫榜 `选题假设.md`：supported、weakened、rejected 或 still_unknown；一本作品不能把市场假设标为 confirmed。

## 进度与恢复

开始阶段前：

```bash
python "<skill-dir>/scripts/analysis_workspace.py" begin \
  --workspace "<拆文工作区>" --stage <0-6> --json
```

阶段产物写完后：

```bash
python "<skill-dir>/scripts/analysis_workspace.py" complete \
  --workspace "<拆文工作区>" --stage <0-6> \
  --artifact "<相对工作区的产物>" --json
```

`complete` 只在阶段顺序正确、产物存在且非空、源文件哈希未漂移时推进。中断后运行 `status`；存在 `in_progress_stage` 时整阶段复核或重跑，不能把半成品视为完成。修改已完成阶段的产物时，重开该阶段并把依赖它的后续阶段标为 stale；当前工具不替 Agent 判断语义依赖，协议默认 Stage N 变化使 N+1 至 6 需要复核。

工具还会校验阶段最小产物集：Stage 0 `来源.md`；Stage 1 `开篇.md`；Stage 2 至少一个 `章节/` 文件；Stage 3 三份剧情文件，其中 `剧情/节奏.md` 与 `剧情/情绪与承诺.md` 至少各有一个标题或 `id:` 条目；Stage 4 人物、设定、章法；Stage 5 `文风.md`；Stage 6 `召回卡.md` 与 `拆文报告.md`。`召回卡.md` 至少含一条 YAML：

```yaml
id: RC-001
function: 功能结论
conditions: 适用条件
source: 章/行
similarity_risk: 换名即复刻的风险
failure_mode: 失败条件
confidence: high | medium | low
```

写作时用 `analysis_workspace.py recall --task planning|chapter|style|review` 只打印已登记路径，不生成正文。这只证明产物存在、字段齐全且绑定当前来源，不证明文学判断正确，仍须执行下方证据验收。

## 事实可溯源

每项硬结论至少包含：

```yaml
claim: 结论
source: 原文件标识 + 章节/行号
evidence: 必要短引文或可复核事实
observation: 文本实际发生什么
inference: 功能解释
confidence: high | medium | low
```

无法定位的印象只能写入待验证，不进入召回卡。聚合发现与逐章证据冲突时保留冲突，不用更顺耳的总结覆盖原文。

## 写作时定点召回

根据当前任务只读最小产物：

| 当前任务 | 召回 |
|---|---|
| 立项 / 选题 | `拆文报告.md` 的承诺与风险 + `召回卡.md` |
| 卷规划 | `剧情/单元.md`、节奏与承诺相关条目 |
| 单章章法 | `章法.md` 中同功能章节 + 对应来源证据 |
| 文风 | `文风.md` 的抽象维度；不复制锚点句法和连续表达 |
| 审稿 | 对应失败模式、适用条件和原始证据 |

一次只选一个主对标功能，可补一个辅助样本做反例。召回内容进入本书前必须按 `comparative-analysis.md` 重映射到本书人物、规则和因果链，并通过原创性复核。对标原文、专名、连续事件和标志性表达不进入正文或本书事实库。

## 验收

- 来源、版本、覆盖和失败章节完整披露。
- 所有阶段状态与实际非空产物一致，可从 `status` 恢复。
- 聚合结论能回到章节或场景证据。
- 章法、情绪、文风和平台信号没有互相冒充。
- `召回卡.md` 只含功能与条件，不含可识别剧情复刻。
- 扫榜假设经过正文拆解后有明确状态和剩余不确定性。
