# 题材工艺路由

题材工艺用于回答“这类故事靠什么持续成立”，不是给正文贴标签，也不是把平台经验写成固定公式。先服从已接受事实、当前章纲和本书 `Style Contract`，再用题材模块校准冲突、信息与场景颗粒。

## 何时使用

- 立项时：确认读者承诺、持续冲突发动机和题材边界。
- 卷规划时：检查中后期是否仍有可升级的压力，而非只够支撑开篇。
- 写章时：只摘取与本章相关的工艺约束，不把整份模块塞进上下文。
- 审稿时：判断作品是否偏离自己的承诺；不能因为“不像某个模板”就判错。

## 选择模块

只完整加载一个主题材模块。混合题材最多再加载一个辅模块，且只取与本书交叉点直接有关的条目。

| 故事主要依靠什么推进 | 加载模块 |
|---|---|
| 谜面、调查、隐瞒、危险信息 | [genre/suspense-mystery.md](genre/suspense-mystery.md) |
| 能力成长、规则探索、资源竞争、世界尺度扩张 | [genre/speculative-progression.md](genre/speculative-progression.md) |
| 爱情、亲情、友谊、婚姻或关系选择 | [genre/romance-relationship.md](genre/romance-relationship.md) |
| 制度、战争、朝堂、家国与多方博弈 | [genre/historical-intrigue.md](genre/historical-intrigue.md) |
| 职业、生活、经营、社区与现实处境 | [genre/urban-life.md](genre/urban-life.md) |

题材不在表中时，选择冲突发动机最接近的一类，只借方法，不强改题材。若本书真正的推进力来自两个母类，明确主次：主题材决定读者首先等待什么，辅题材只增加压力或关系维度。

## 生成本书题材契约

立项或接管旧稿时，输出一页以内的 `Genre Contract`：

```markdown
# Genre Contract
- 主题材 / 辅题材：
- 读者承诺：读者持续等待的具体体验或问题
- 核心发动机：哪组欲望、阻力和规则能反复产生不同选择
- 信息规则：读者、视角人物和其他角色分别何时知道什么
- 典型场景颗粒：本书最有辨识度的任务、空间、物件或关系动作
- 升级维度：难度、代价、关系、认知、规模中哪些会变化
- 兑现方式：阶段性结果如何改变人物处境
- 禁止漂移：哪些写法会背叛本书承诺
- 当前假设：尚未由样章或用户确认的判断
```

契约是创作约束，不是事实账本。已经发生的人物、地点、物品、时间线和伏笔仍由连续性系统管理。

## 工艺应用顺序

1. 先找本场景的欲望、阻力、选择、代价和状态变化。
2. 再用主题材模块决定压力以何种材料显形，例如证据、资源、礼法、工作结果或关系行为。
3. 辅题材只补一个当前必要维度，不能抢走主题材的兑现。
4. 最后以人物身份、经验和现场条件改写，确保场景只能由本书的人物作出。

同一发动机再次出现时，至少改变一项条件：人物所知、可用资源、关系位置、风险承担者、规则理解或结果归属。只换地点和对手不算升级。

## 验收

- 删去题材标签后，仍能从人物选择、场景材料和结果看出作品的核心体验。
- 题材机制制造了新选择，不只是给既定情节换皮。
- 兑现来自前因、人物行动与代价，不来自临时降智或无铺垫救援。
- 中后期升级没有没收主角能动性，也没有过早耗尽终局答案。
- 平台偏好仅作为待验证假设；不存在固定爽点间隔、固定对话占比或每章同一种钩子。
