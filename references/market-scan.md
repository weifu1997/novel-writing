# 扫榜与选题验证

扫榜用于建立有日期、有来源的市场假设，不负责保证流量。只有用户要求市场方向、榜单分析、商业选题或平台近期趋势时加载；普通写作不自动联网或扩大研究范围。

## 1. 锁定研究问题

```markdown
- 目标平台 / 频道 / 地区：
- 榜单与时间窗口：
- 长篇 / 短篇：
- 用户已有方向：
- 需要回答的决策：选题、篇幅、开篇、卖点、竞争或平台适配
- 样本上限与停止条件：
```

跨平台比较必须分别记录平台指标含义，不能把在读、收藏、月票、销售和编辑推荐当成同一尺度。

## 2. 获取样本

按以下优先顺序使用当时可用且获准的方式：

1. 用户提供的榜单文件、截图、文字或链接。可用 `market_fetch.py --markdown-file` 把粘贴的榜单转成记录数组。
2. 起点移动端公开页可用 `market_fetch.py --qidian-mobile hotsales|yuepiao|signnewbook|newsign`；冻结 HTML 用 `--html-file`。解析失败即停止，不手补排名。番茄、七猫、晋江不内置采集。
3. 其他官方公开页使用当前环境可用的网页访问工具。
4. 无实时访问能力时使用已有历史数据，但必须标为 `historical`，不得声称当前趋势。

遵守登录、访问权限、站点条款和用户授权。不要绕过验证、付费或访问控制；页面无法可靠读取时报告缺口，不凭记忆补排名和指标。平台页面结构易变，因此本 skill 不把第三方 CSS 选择器写成长期真相。

每条样本先写入统一 JSON：

```json
{
  "platform": "平台",
  "list_name": "榜单",
  "captured_at": "2026-09-16T10:00:00+08:00",
  "rank": 1,
  "title": "作品名",
  "author": "作者或 null",
  "url": "公开来源 URL 或 null",
  "category": "平台分类或 null",
  "length": 123456,
  "status": "连载/完结或 null",
  "tags": ["标签"],
  "metrics": {"平台原字段": "原值"},
  "synopsis": "公开简介或 null",
  "source_mode": "live | user_provided | historical"
}
```

保留平台原指标名和值，不根据不可比字段计算跨平台总分。相同作品出现在多个榜单时保留各次观测，并通过作品名、作者和 URL 辅助识别重复。

## 3. 数据质量门禁

将记录数组交给：

```bash
python "<skill-dir>/scripts/market_sample.py" <样本.json> \
  --min-records <最低样本数> --min-lists <最低榜单数> \
  --max-age-days <允许时效> --json
```

报告检查字段、排名、时间、重复观测、来源模式、URL 与样本规模。`block` 表示数据不能支持当前结论；`warn` 可以继续，但每条结论必须降低 confidence 并披露缺口。默认阈值只是数据质量下限，不是“达到 N 本就证明趋势”。

截图或手工录入无法提供 URL 时允许为 null，但应保留来源说明；`historical` 样本不因格式完整自动升级为当前趋势证据。

## 4. 分析层次

先描述，再比较，最后形成假设：

- 样本构成：平台、榜单、日期、频道、有效条目和缺失字段。
- 重复信号：题材组合、主角处境、核心机制、简介承诺、篇幅与更新状态。
- 榜单差异：新书榜、畅销榜、完结榜或编辑榜分别证明什么、不证明什么。
- 竞争与饱和：同质样本集中度、头部作者偏差、样本是否被单一作品带动。
- 项目适配：用户素材、能力、篇幅和风险能否支持该方向。

榜单列表只能支持书名、标签、简介和公开指标层判断。没有合法可读正文时，不得据此断言具体章法、反转或文风；这些结论必须进入拆文阶段取证。

## 5. 选出拆文样本

不要只选排名第一。按决策问题选择：

- 一个近期强信号样本。
- 一个稳定同题材样本。
- 一个非唯一头部、对新作者更可比的样本。
- 必要时一个失败或弱信号对照样本。

每本记录选择理由、要验证的假设、合法文本来源和停止条件。样本不足时输出“待验证选题”，不进入确定性开书结论。

## 6. 扫榜产物

```text
研究/扫榜/{scan-id}/
|-- 样本原始.json
|-- 数据质量.json
|-- 扫榜报告.md
`-- 选题假设.md
```

报告至少包含数据日期、来源模式、覆盖榜单、质量状态、发现、反例、confidence、有效期和建议复扫时间。选题假设使用：

```markdown
| ID | 假设 | 榜单证据 | 反例/偏差 | 项目适配 | confidence | 拆文验证动作 | 状态 |
|---|---|---|---|---|---|---|---|
```

只有经过 [deconstruction-pipeline.md](deconstruction-pipeline.md) 的正文证据验证后，才能把“简介层信号”升级为“章法或结构结论”。
